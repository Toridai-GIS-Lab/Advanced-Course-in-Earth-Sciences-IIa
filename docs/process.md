# 過程が残る道具を使う

この講義でCLIを使う理由は、速いからでも、玄人っぽいからでもありません。
**処理の過程が、そのまま残るから** です。

## 同じ地図を作る、2つの道

「岡山県の標高データを、平面直角座標系に変換して、県の範囲で切り抜く」。
同じ結果を、2つの道で作ってみます。

=== "GUIの道"

    1. QGISでDEMを開く
    2. メニュー「ラスタ」→「投影法」→「再投影」を選ぶ
    3. 出力CRSのボタンを押し、検索欄に「6673」と入力して選ぶ
    4. リサンプリング方法のプルダウンから「バイリニア」を選ぶ
    5. 出力先を選んで「実行」
    6. 「ラスタ」→「抽出」→「マスクレイヤで切り抜き」を選ぶ
    7. マスクレイヤに県境を選び、「切り抜き範囲にクロップ」にチェック
    8. 「実行」

    結果の地図は残ります。**8つの操作は、どこにも残りません。**

=== "CLIの道"

    ```bash
    gdal raster pipeline \
      read dem.tif ! \
      reproject -d EPSG:6673 -r bilinear ! \
      clip --like okayama.gpkg ! \
      write dem_okayama_6673.tif
    ```

    結果の地図と、**それを作った手順そのもの** が残ります。

出来上がる地図は同じです。違うのは、作り方が手元に残るかどうかです。

## 確かめられると、何が違うのか

作り方が残っていると、次のことができます。

- **間違いを見つけられる**：「リサンプリングは何にした？」に、記憶ではなく記録で答えられる
- **直せる**：座標系を間違えていたら、1か所を書き換えて再実行すればよい
- **他のデータに使える**：県名を変えれば、隣の県にもそのまま使える
- **他人が確かめられる**：指導教員・共同研究者・査読者が、同じ結果を出せる

研究では、最後の「他人が確かめられる」が決定的に重要です。

## 🔴 見分け方は、一つだけ

ある道具が「過程が残る道具」かどうかは、次の問いで判定できます。

> **「これをもう一度出してください」と言われて、手順を人に渡せるか。**

| 渡せるもの | 渡せないもの |
|------------|--------------|
| コマンド、シェルスクリプト | ダイアログでクリックした設定 |
| Python / R のコード | 口頭でしか説明できない操作 |
| QGISのモデル、処理履歴に残ったコマンド | 手で修正した頂点、手で塗り直したセル |
| Gitのコミット履歴 | 「たしかこうした」という記憶 |

右側の操作は、行った瞬間に **元データとのつながりが切れます**。
結果のファイルはあっても、それが元データからどう作られたのかを誰も証明できません。

この講義全体の方針、**「手で直さない。直すならコマンドで直す」** の根拠はここにあります。

## 🔴 「ポチポチ」は、修行ではない

GUIで何十回もクリックして作った地図には、苦労の分だけ愛着が湧きます。
しかし、その苦労は次回に引き継げません。データが1つ増えれば、同じ苦労をもう一度します。

### 苦労した時間の長さは、身についたことの量ではありません

100個のファイルを手で変換した経験から学べることは、1個目でほぼ尽きています。
残りの99回は、**ループを1行書けば済んだ時間** です。
苦労を減らすことは手抜きではありません。考えるべきことに時間を回すことです。

## AIにも、同じことが当てはまります

生成AIに「このデータを変換して」と頼むと、コマンドやコードを返してくれます。
これ自体は「渡せる手順」です。問題になるのは、次の場合です。

- AIの回答をチャット画面で読んで、**手で打ち直して** 実行した
- 動くまで何度も書き換えたが、**最終的に何を実行したか** を保存していない
- AIが「処理しました」と言った結果の数値を、**そのまま報告書に写した**

AIを使ってよいかどうかではなく、**AIを使った後に手順が残っているか** が問題です。
AIが書いたコマンドもスクリプトファイルに保存し、自分で実行し、結果を確かめてください。

## 誤解しないでほしいこと

- **GUIが悪いわけではありません。** データを眺める、結果を目で確認する、地図を仕上げる――こうした作業はGUIの方が得意です。この講義でもQGISを使います。
- **GUIでも過程は残せます。** QGISのプロセシング履歴には、実行したGDALコマンドが記録されています。モデルデザイナで手順を保存することもできます。大事なのは道具の種類ではなく、手順を渡せる形で残すことです。
- **全部をCLIでやる必要はありません。** 探索はGUI、確定した処理はCLI、という使い分けが現実的です。
